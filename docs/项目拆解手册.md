## 第 1 章 · 业务理解：先懂生意，再懂数据

### 1.1 这是一家什么店？

英国在线礼品零售商（UCI Online Retail 数据集背后的真实公司），主营**手工风节日礼品**（蜡烛台、彩旗、陶瓷罐、圣诞饰品等），客户以**英国本土批发企业（B2B）为主**，也有海外批发客户。理解三个业务特征，后面的所有结论才顺理成章：

1. **B2B 批发**：客单价高（£466）、订购量波动大、"客户=公司采购员"；
2. **强季节性**：圣诞备货季（9-11 月）是全年高峰，1 月是退货高峰；
3. **线下 + 平台混合渠道**：数据里混有亚马逊平台费冲销（AMAZONFEE），说明这家店同时在亚马逊上卖。

### 1.2 电商核心指标名词表（面试必备，答不上=基本功不扎实）

| 指标 | 全称/公式 | 本项目中的值 |
| --- | --- | --- |
| GMV | 成交总额 Σ(数量×单价) | £855 万 |
| 订单数 | 发票号去重 | 18,361 |
| AOV 客单价 | GMV / 订单数 | £466 |
| ARPPU | GMV / 活跃付费客户数 | 月均 £639 左右 |
| RFM | Recency/Frequency/Monetary | 8 分层 |
| Cohort 留存 | 同期群按月复访率 | 次月 20.4% |
| 退货率（金额口径） | 退货金额/(退货+销售) | 商品口径 3.50% |

> **面试考点**：被问"你做过什么分析"时，先报业务背景（一句话），再报核心数字（三五个），最后才讲方法。顺序反了会显得像背代码的。

### 1.3 为什么选这 7 个业务问题？

分析不是"把会画的图都画一遍"，而是模拟真实分析师接到的**经营诊断需求**：老板想知道"生意好不好（Q1）→ 客户怎么样（Q2/Q3）→ 货怎么样（Q4）→ 市场怎么样（Q5）→ 客户什么时候买（Q6）→ 哪里在漏水（Q7）"。这是一个**漏斗式的诊断框架**：先总量、再结构、再问题定位。

## 第 3 章 · 清洗拆解（对应 Notebook 01）

### 3.1 方法论：先"体检"再"动刀"

拿到数据**不要立刻删**，先量化"脏"在哪。体检四查：

| 查什么 | 代码 | 本数据的结果 |
| --- | --- | --- |
| 缺失 | `raw.isna().sum()` | CustomerID 缺 135,080 行（24.9%） |
| 重复 | `raw.duplicated().sum()` | 5,268 行完全重复 |
| 异常值 | `describe()` + 布尔筛选 | 数量≤0 有 10,624 行；单价≤0 有 2,517 行 |
| 口径 | 时间范围/类型检查 | 末日 2011-12-09 只采集到 12:50；发票里混非商品行 |

### 3.2 每一步清洗的"为什么"（面试的核心考点）

清洗不是技术动作，是**一连串业务决策**：

1. **剔除 2011-12-09（1,632 行）**：当天只采集到中午。不删的话月度趋势图上 12 月会"暴跌 71%"，业务方会误以为经营出事。**先对齐口径，再看趋势。**
2. **拆分退货表（10,617 行）而不是删除**：C 开头发票/负数量是"取消与退货"，它们不是错误数据，而是 Q7 专题的核心分析对象。**拆分优于丢弃。**
3. **剔除缺失 CustomerID 的销售行（约 24%）**：客户分析（RFM/留存）必须归属到人。这部分多为无主批发展客，留着会污染客户层；剔除前先算它占的金额并在报告中披露占比。**动手前先量化损失。**
4. **剔除非商品行**：POST（运费）、BANK CHARGES（手续费）、M（手工调整）、AMAZONFEE（亚马逊费用）、D/DOT/C2/CRUK 等。它们会让"商品 GMV 榜"出现"运费冠军"。
5. **剔除单价≤0**：0 元行多为赠品/坏账调整，混入会拉低 AOV。
6. **去重（5,268 行）**：完全重复行会虚增 GMV。
7. **派生字段**：`Revenue = Quantity × UnitPrice`（核心度量）、`InvoiceMonth`（月度分析主口径）、CustomerID 转整型。

**清洗结果**：541,909 → 销售 390,545 行（72.1%）+ 退货 10,617 行，全程打印清洗日志表，每步可回溯。

### 3.4 面试考点

- "为什么缺失客户 ID 要删而不是填充？"——客户 ID 是**标识列**不是特征列，填充（如填 -1）会把一群不同客户假装成一个"客户"，RFM/留存全错；正确做法是剔除+披露占比，或建议业务补录。
- "去重会不会误删合法数据？"——本项目删的是**全列完全相同**的行（同发票同行商品同时间同价格），业务上不可能是一笔独立交易。
- "如果清洗后结果反常识怎么办？"——先查清洗代码，再回原始数据核对样例，最后与业务确认口径；不悄悄改数据。

## 第 4 章 · 分析拆解（对应 Notebook 02）

### Q1 经营概况：生意在变好还是变坏？

- **指标**：月度 GMV、订单数、活跃客户数、AOV、ARPPU、GMV 环比。
- **代码要点**：`groupby('InvoiceMonth').agg(GMV=('Revenue','sum'), 订单数=('InvoiceNo','nunique'), ...)`——用**命名聚合**一次算全；`pct_change()` 求环比。
- **结果**：总 GMV £855 万；9/10/11 月为旺季（11 月 £113.7 万封顶）；2 月（£44.2 万）、4 月（£45.4 万）为低谷；AOV 围绕 £466 波动、无趋势。
- **洞察链条**：AOV 无趋势 + GMV 随订单量同向波动 ⇒ 增长动能不在"提价"而在"客户数与留存" ⇒ 引出 Q2/Q3。
- **面试考点**：为什么 GMV 涨不一定是好事？（可能是大客一次性补货，也可能是促销透支——要拆客户结构与 AOV 交叉看。）为什么 2011-12 只有 £32.8 万？（口径截断，只含 12/1-12/8，**不是暴跌**。）

### Q2 客户价值：RFM 八分层

- **定义**：R=快照日（2011-12-09）减最近购买日的天数；F=购买发票数；M=累计消费额。
- **打分**：三维各按**四分位**打 1~4 分。用分位数而不是拍脑袋阈值，理由：这是**相对分层**，换一家店阈值完全不同，分位数法可迁移。
- **关键代码坑**（面试高光时刻）：

```python
rfm['R_score'] = pd.qcut(rfm['R'].rank(method='first'), 4, labels=[4,3,2,1]).astype(int)
```
> F 分布严重右偏（一半客户只买过 1 次），直接 `qcut` 会因重复分位点报错或切分失真；先 `rank(method='first')` 给每个客户唯一名次再分箱。R 的 labels 是 `[4,3,2,1]`——**R 越小分越高**，方向别搞反。

- **分层规则**：R/F/M 各分高（≥3）低 → 8 类：重要价值/发展/保持/挽留 + 一般价值/发展/保持/挽留。每类对应一套运营动作（价值=留、发展=提频、保持=唤醒、挽留=召回）。
- **结果**：重要价值客户 1,311 人（30%）贡献 74% GMV；一般挽留客户 1,249 人（29%）只贡献 4%；重要挽留客户 268 人是最优先召回人群。
- **面试考点**：① 为什么不用 K-Means 聚类做用户分层？（RFM 分层可解释、可直接映射运营动作；聚类需要调参和业务命名，样本分布解释成本高——两者都做过才有的比较，见面试问答手册。）② F 用"发票数"还是"购买天数"？（发票数=订单次数；也有口径用购买天数去重，差异小但要说明。）③ 快照日为什么 +1 天？（让"最后一次购买就在数据最后一天"的 R=1 而不是 0/负数，且语义自然。）

### Q3 用户生命周期：Cohort 同期群留存

- **方法**：按客户"首次购买月"分组 → 计算每个群在第 0/1/2...月的去重客户数 → 除以群规模得到留存率矩阵。
- **代码要点**：月差用 `(年差)*12 + 月差` 手工计算期数；`pivot_table(index='首次购买月', columns='期数', values='CustomerID', aggfunc='nunique')`。
- **结果**：平均次月留存 20.4%（= 80% 的客户买一次就走）；2010-12 群（圣诞获客）次月留存 36% 显著更高；后期月份群稳定在 15~23%。
- **洞察链条**：留存差是常态而非某月事故 ⇒ 问题在"首购后的承接动作缺失" ⇒ 建议搭建首购后 7/30 天自动化触达。
- **面试考点**：① 为什么不直接算"月度复购率"？（总盘子复购率把"老客占比变高"和"留存变差"混在一起；cohort 把获客质量随时间的变化拆开。）② 末位群（2011-12）为什么是 NaN？（没有未来数据，**不可计算**；SQL 里会算成 0，语义不同——我们用 SQLite 校验时专门处理了这个差异，见 sql/verify_sqlite.py。）

### Q4 商品分析：帕累托集中度

- **方法**：按 StockCode 聚合 GMV 与销量 → Top10；再算累计 GMV 占比曲线。
- **结果**：3,658 个 SKU 中，前 796 个（21.8%）贡献 80% GMV；Top1 是 REGENCY CAKESTAND 3 TIER（£14.2 万）。
- **洞察**：头部集中 ⇒ 库存/选品/陈列资源向头部倾斜，长尾做减法。
- **面试考点**："为什么用 GMV 而不用销量排名？"（批发场景单价差异大，销量大≠贡献大；有成本数据时应改用毛利——呼应局限性。）

### Q5 市场结构

- **结果**：英国 82.6%；荷兰 9 客户 £28.4 万、爱尔兰 3 客户 £25.7 万（**巨鲸型**）；德国 93 客、法国 87 客（**分散型**）。
- **洞察**：巨鲸市场做客户关系管理（防单点流失），分散市场做本地化增长。同一张国家榜，按客户数再切一刀，就能读出两种完全不同的市场结构——**同一指标的多口径下钻**是加分思维。

### Q6 时段规律

- **方法**：星期×小时的发票数热力表（`dt.dayofweek`、`dt.hour` + pivot_table）。
- **结果**：工作日 10:00-15:00 集中，周三 12 点 609 单封顶；**周六全天空缺**（批发客户周六不采购，真实业务特征）。
- **洞察**：B2B 时间指纹 ⇒ 营销推送/客服排班对齐工作日上午，周末投放是浪费。
- **面试考点**："周六没数据，是数据错了吗？"——不是。先验证（全周六行为 0，而非部分缺失），再结合 B2B 业务解释，最后写入结论作为业务事实。

### Q7 退货诊断（本项目最有故事的一章）

- **发现 1（口径陷阱）**：退货表混着 AMAZONFEE（£23.5 万）、M 手工调整（£14.7 万）等**非商品冲销行**，占退货流水 57%。流水口径退货率 7.84%，**真实商品退货率只有 3.50%**。不拆口径，"退货治理"会完全跑偏。
- **发现 2（结构性）**：商品退货集中在少数 SKU：陶瓷储物罐一个商品占全年商品退货 25%。
- **发现 3（节日效应）**：2011 年 1 月商品退货率冲到 14%（圣诞礼品节后退货潮），其余月份 1~4% 平稳。
- **面试考点**：这是**"数据分析师价值"的最佳证明题**——不是算了多少指标，而是**发现口径里的坑并纠正了业务判断**。讲项目时务必把这段放在高潮位。

## 第 6 章 · 结论与建议的推导链条

**每个建议都是"发现→归因→动作→预期指标"四段式**，这是业务分析与"数据观后感"的区别。五条结论一览：

| # | 数据发现 | 业务归因 | 落地动作 | 预期指标 |
| --- | --- | --- | --- | --- |
| 1 | 次月留存仅 20.4%，老客收入占比走高 | 首购后无承接动作 | 首购后 7/30 天自动化触达 + RFM 圈人 | 次月留存 20%→30% |
| 2 | 30% 客户贡献 74% GMV；21.8% SKU 贡献 80% GMV | 无差异化运营 | VIP 服务 / 挽留召回 / 头部保库存 / 长尾清退 | 召回率↑ 缺货率↓ |
| 3 | 荷兰/爱尔兰巨鲸型，德法分散型 | 服务本地化不足 | 巨鲸点对点维护；德法本地化增长 | 海外 GMV 占比↑ |
| 4 | 工作日 10-15 点集中，周六停业 | B2B 时间指纹 | 推送对齐工作日上午；周末预算转自动化 | 触达转化率↑ |
| 5 | 商品退货率 3.5%，集中在陶瓷罐；1 月圣诞退货潮 | 易碎品包装不足 | 包装升级+质检前置；财务冲销单列台账 | 黑名单商品退货率↓ |

**局限性**（主动说，是加分不是示弱）：无浏览数据（做不了转化漏斗）、无成本数据（按 GMV 排名可能高估低毛利品）、仅 13 个月（同比不可靠）、25% 客户 ID 缺失（无主客户价值可能被低估）。
