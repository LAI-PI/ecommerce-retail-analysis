# 简历写法 —— 项目经历怎么摆、怎么写、怎么讲

## 一、定位：它替代哪个位置

你简历上原来的"主位"项目是 **基于 Spark 全组件的电影大数据分析系统**（MLlib 调参 RMSE、GraphX、Streaming），它是**纯技术型**项目：证明会用大数据组件，但通篇没有业务问题、没有结论建议——面试官看不出你"用数据做了什么决策"。微博舆情项目同理（采集→分词→出图，缺业务闭环）。新项目 **英国电商经营诊断分析** 上位成主位，形成组合：

| 位置 | 项目 | 传递的信号 |
| --- | --- | --- |
| 主位 | 英国电商经营诊断分析 | 会用数据回答业务问题、推动决策（数据分析师核心能力） |
| 第二 | Spark 电影数据分析 | 大数据技术栈深度（SparkSQL/MLlib/Streaming） |
| 第三 | 微博舆情分析 | 数据采集 + 文本挖掘（Requests/Jieba/情感分析） |

> 面试官读到组合后的印象：**业务分析为主线，技术栈有纵深，采集清洗可视化的基本功全覆盖。** 对"数据分析实习生"岗位，主位项目必须业务型——这正好补上你简历最大的短板。

## 二、简历项目经历模板（可直接抄改）

> **英国电商经营诊断分析**（Python / pandas / SQL / matplotlib） · 2026.09
> 项目链接：github.com/<你的用户名>/ecommerce-retail-analysis
>
> - 基于 UCI 公开的英国电商 54 万行真实交易数据，独立完成"业务问题→清洗→分析→可视化→结论建议"全流程，围绕经营趋势、RFM 分层、同期群留存、商品集中度、市场结构、时段规律、退货诊断 7 个业务问题输出 11 张图表与 5 条落地建议；
> - 设计"体检四查→逐条清洗"流程，处理客户 ID 缺失（25%）、口径截断（不完整日）、取消单拆分等 6 类数据问题，清洗全程留痕可回溯；
> - 构建 RFM 八分层模型：发现重要价值客户以 30% 人数贡献 74% GMV；通过同期群分析定位"次月留存仅 20.4%"为最大增长漏水口，提出首购后自动化触达方案；
> - 拆分退货口径，识别退货流水 57% 为平台费冲销，将真实商品退货率从 7.84% 修正至 3.50%，锁定易碎品退货黑名单（单品占比 25%）；
> - 将全部分析用 MySQL 窗口函数（NTILE / 累计和 / CTE）复写为 SQL 版本，并编写自动化脚本验证 SQL 与 pandas 结果一致性。

**写法要点**：
1. 每条 bullet = 动词 + 方法 + 数字结果；第 3、4 条是"亮点弹"，放最有记忆点的两个发现；
2. 所有数字必须能被你讲清楚（面试官随便挑一个问你）；
3. 链接必须可点、README 首屏就有图——面试官大多只看 30 秒。

## 三、对现有简历的具体修改建议

1. **项目经验区**：把电商项目放第一位（用上面模板），Spark 电影项目退居第二，微博舆情第三；每段经历的第一条 bullet 写"做了什么+数字结果"，不要只写技术栈；
2. **技能评级区**：SQL 那行的描述从"查询/多表联查"升级为"多表联查/**窗口函数**"（本项目 NTILE/累计和/CTE 都是你能讲的实例）；Python 分析行可加"独立完成端到端业务分析项目"；
3. **个人简介**：加一句业务分析定位，如"已完成电商经营诊断完整项目，擅长从数据口径到业务建议的完整闭环"；
4. **求职意向**：数据分析实习生（主）不变——本项目正是按实习岗可讲深度设计的（口径管理、RFM、留存，面试官不会拿工作年限项目刁难你）。

## 五、面试中三个项目的联动话术

- 被问"你会 SQL 吗" → 熟练多表联查（微博舆情/电影项目取数），电商项目里用窗口函数写了 NTILE 打分、累计和帕累托、CTE 同期群，并有自动化验证脚本保证与 pandas 一致；
- 被问"Spark 项目和电商项目有什么区别" → 一个是技术练兵（组件全覆盖、调 RMSE），一个是业务诊断（问题→口径→结论→建议）；面试官追问业务细节时，电商项目就是你的主场；
- 被问"为什么都是公开数据集，没有公司真实数据" → 如实答实习经历有限，但正因如此刻意选了真实交易数据（UCI，54 万行）并按公司内真实分析流程做：口径对齐、清洗留痕、结论可落地——**方法论是公司级的**。
